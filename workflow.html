PlexusBiz Automate Workflow

Senior implementation tracker for the PLEXUS CLOUD B2B E-Commerce and Business Automation Platform.

Project PlexusBiz-Automate
Stack Laravel 10+, React, Tailwind CSS, MySQL
Architecture Modular Monolith by domain
Repository Rule Commit and push after each completed part

Operating Rules

  • Read this workflow before starting any new implementation part.
  • After completing one part, update this file, commit with a short senior-style message, and push immediately.
  • Do not batch unrelated finished parts into one commit or one push.
  • Use production-grade code only; no placeholder examples for required platform logic.
  • Use React for interactive screens and Tailwind CSS for UI styling.
  • Keep credentials and provider secrets in .env; never commit real secrets.
  • Use a Modular Monolith structure: domain code must be grouped by business area such as ECommerce, CRM, Automation, Marketing, Social, Support, Admin, and Settings.
  • Every automation execution must write a workflow_logs row with the full JSON trigger payload snapshot, status, result, error, and executed timestamp.
  • External email, SMS, Facebook, and Instagram integrations must be adapter-based and mockable until real credentials are configured.

Current Decisions

  • Laravel will own domain logic, persistence, APIs, events, queues, scheduler, policies, and notifications.
  • React will own dynamic application screens through Vite while Laravel provides backend routes and API boundaries.
  • Tailwind CSS will be the only UI utility framework.
  • Automation payload logging is mandatory and must preserve full trigger context as JSON, not just selected fields.
